# 验证方案

> 三层递进验证：L1 功能验证 → L2 质量验证 → L3 价值验证

## L1：功能验证（产品能不能用）

### 自动化测试

| 测试项 | 输入 | 期望输出 | 通过标准 |
|--------|------|---------|---------|
| 正常 JD 解读 | 标准 JD 文本 | 四维结构化报告 | 报告完整生成 |
| 长 JD 解读 | 500+ 字 JD | 正常解读（不截断） | 所有维度都有内容 |
| 短 JD 解读 | 50 字以内 JD | 正常解读（不幻觉） | 不编造 JD 未提及的内容 |
| 空输入 | 空文本 | 友好错误提示 | 提示"请输入 JD 内容" |
| 特殊字符 | 含 emoji/特殊符号的 JD | 正常解读 | 不崩溃，正常输出 |
| 岗位类别匹配 | 选择"前端" + 前端 JD | 注入前端经验 | 报告含前端相关经验 |

### 手工测试

- [ ] 小程序在各机型上的显示正常
- [ ] 解读报告格式正确、排版清晰
- [ ] 加载状态和错误状态都有友好提示
- [ ] 历史记录功能正常

**L1 通过标准**：所有自动化测试通过 + 手工测试无阻塞性问题

## L2：质量验证（AI 输出好不好）

### 评估方法

选取 10 条真实 JD（覆盖不同岗位），每条生成解读报告，由 2-3 人按质量评估量表打分。

### 评估量表

| 维度 | 1 分 | 3 分 | 5 分 |
|------|------|------|------|
| **真实性** | 明显编造 | 部分可信 | 与真实工作高度一致 |
| **完整性** | 遗漏重要信息 | 基本覆盖 | 完整覆盖 JD 所有要点 |
| **具体性** | 全是空话 | 有一些具体描述 | 每条都具体到可操作 |
| **可执行性** | 无法据此行动 | 有方向但不够具体 | 可以直接照做 |
| **差异化** | 和直接看 JD 没区别 | 有一些额外信息 | 显著超越 JD 原文的价值 |

### 评估记录模板

```
JD 编号：001
岗位：前端开发工程师
来源：BOSS 直聘

评分：
- 真实性：4/5（工作内容描述基本准确，但"性能优化"部分偏泛）
- 完整性：4/5（覆盖了主要要求，遗漏了"熟悉 CI/CD"）
- 具体性：3/5（"熟练掌握 JavaScript"还是偏空泛）
- 可执行性：4/5（学习路径具体，但时间估算偏乐观）
- 差异性：4/5（"JD vs 真实情况"对比很有价值）

总分：19/25
通过：✅（≥ 20 为优秀，≥ 15 为通过）

改进建议：
- 能力要求部分需要更具体的描述
- 时间估算需要更保守
```

### L2 通过标准

- 平均总分 ≥ 20/25（优秀）
- 单条最低分 ≥ 15/25（无严重不合格）
- 幻觉率 < 10%（不超过 1 条 JD 出现明显编造）

## L3：价值验证（用户觉得有没有用）

### 用户试用方案

**目标**：5-10 位目标用户（毕业 0-2 年，正在求职）

**流程**：
1. 用户自行输入一条自己感兴趣的 JD
2. 使用产品生成解读报告
3. 填写反馈问卷（5 分钟）

### 反馈问卷设计

```
1. 这个解读报告对你有帮助吗？（1-5 分）
2. 报告中哪个部分对你最有价值？（多选）
   □ 真实工作内容  □ 能力要求  □ 从业者经验  □ 行动建议
3. 报告中有哪些内容你觉得不准确或没用的？（开放题）
4. 读完报告后，你打算采取什么行动？（开放题）
5. 你愿意把这个工具推荐给朋友吗？（0-10 分，NPS）
6. 如果这个工具收费 5 元/次，你愿意付吗？（愿意/不愿意/看情况）
7. 你还希望这个工具增加什么功能？（开放题）
```

### L3 通过标准

| 指标 | 目标 | 说明 |
|------|------|------|
| 有用度评分 | > 4/5 | 核心价值验证 |
| 推荐意愿（NPS） | > 30 | 口碑传播潜力 |
| 行动转化率 | > 30% | 用户是否打算采取行动 |
| 付费意愿 | > 15% | 商业化可行性 |

## 验证结果使用

验证结果不仅用于参赛展示，更重要的是**指导迭代**：

| 验证结果 | 迭代动作 |
|---------|---------|
| L1 不通过 | 修复 bug，不进入 L2 |
| L2 质量不达标 | 优化 Prompt / 补充知识库 |
| L3 用户不满意 | 回到需求理解，重新审视产品方向 |
| 某个维度持续低分 | 针对性优化该维度 |
