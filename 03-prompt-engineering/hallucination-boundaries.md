# 幻觉边界规则（Hallucination Boundaries）

> 版本：V1.0
> 日期：2026-04-18
> 目的：在 Prompt 层面设立硬规则，减少 AI 合成数据和解读报告中的幻觉风险

---

## 一、问题定义

"JD 真话"产品的核心价值主张是"真实从业者经验"，但当前种子数据均为 AI 合成数据，存在以下幻觉风险：

| 风险类型 | 具体表现 | 严重程度 |
|----------|---------|---------|
| 编造来源 | 声称"访谈了某公司工程师"但实际未发生 | 🔴 高 |
| 编造数据 | 虚构具体薪资数字、公司规模、招聘市场数据 | 🔴 高 |
| 过度泛化 | 将个别经验描述为"普遍情况" | 🟡 中 |
| 过时信息 | 引用可能已过时的技术栈版本或市场行情 | 🟡 中 |
| 确信度伪装 | 对不确定的信息使用确定性的表述 | 🟡 中 |

---

## 二、Prompt 层面的硬规则（必须注入系统 Prompt）

### 规则 1：禁止编造具体来源

```
❌ 禁止："根据对字节跳动前端工程师的访谈..."
❌ 禁止："某大厂 HR 表示..."
✅ 允许："根据公开社区讨论和从业者分享..."
✅ 允许："从业者的普遍反馈是..."
```

**Prompt 注入**：
```
你提供的所有经验信息必须基于注入的知识库数据。如果知识库中没有相关信息，
你可以说"根据公开信息，从业者的普遍经验是..."，但绝对不能编造具体的
公司名称、人名、访谈场景作为信息来源。
```

### 规则 2：禁止编造具体数字

```
❌ 禁止："该岗位平均薪资 15-25K"
❌ 禁止："约 70% 的公司要求..."
❌ 禁止："面试通过率约为 30%"
✅ 允许："薪资范围通常与公司规模和城市相关"
✅ 允许："不同公司要求差异较大"
```

**Prompt 注入**：
```
不要编造任何具体的薪资数字、百分比、统计数据。如果需要提到薪资或市场行情，
使用模糊但诚实的表述，如"因公司和城市而异"、"通常在行业中等水平"。
如果用户询问具体数字，明确告知"这需要查阅最新的招聘平台数据"。
```

### 规则 3：标注不确定性

```
❌ 禁止："这个岗位主要做 CRUD 开发"（过于确定）
✅ 允许："在大多数初级岗位中，日常工作以 CRUD 开发为主"（有前提条件）
✅ 允许："部分公司可能要求..."（承认不确定性）
```

**Prompt 注入**：
```
对于不确定的信息，必须使用以下表述方式之一：
- "在大多数情况下..."
- "部分公司可能..."
- "这因团队和公司而异..."
- "根据公开信息的普遍反馈..."

避免使用绝对化的表述，如"一定"、"肯定"、"所有公司都"。
```

### 规则 4：JD 原文优先原则

```
❌ 禁止：忽略 JD 中明确写的内容，用自己的推测替代
✅ 允许：在 JD 原文基础上补充"可能的真实含义"
```

**Prompt 注入**：
```
解读 JD 时，必须严格遵循以下优先级：
1. JD 原文明确写的内容 → 直接引用，不曲解
2. JD 中模糊/夸大的描述 → 结合知识库经验进行翻译
3. JD 中未提及的内容 → 不要主动添加，除非用户明确询问

对于"JD 潜台词"维度，必须明确标注"JD 原文"和"推测的真实含义"的对应关系，
不要将推测当作事实呈现。
```

### 规则 5：知识库数据诚实标注

```
❌ 禁止："根据真实从业者访谈..."
✅ 允许："根据从业者社区公开讨论整理的经验..."
```

**Prompt 注入**：
```
在引用知识库中的经验信息时，使用以下表述：
- "根据从业者社区公开讨论整理..."
- "从业者的普遍反馈是..."

不要声称这些信息来自"真实访谈"或"一手调研"。
```

## 三、解读报告中的数据来源声明

在每份解读报告的底部，必须包含以下声明：

```
📌 数据来源说明
本报告基于 AI 对招聘 JD 的分析和从业者社区公开信息整理。
经验数据仅供参考，可能不完全适用于所有公司和团队。
建议结合具体公司的招聘信息和在职从业者的反馈做综合判断。
```

## 四、种子数据层面的改进

### 4.1 修改 meta.source_type 枚举

| 原值 | 新值 | 说明 |
|------|------|------|
| interview | ai_synthesized_interview | AI 模拟的访谈数据 |
| community | ai_synthesized_community | AI 模拟的社区整理数据 |

> 后续获取到真实数据后，新增 source_type：
> - `real_interview`：真实访谈
> - `real_community`：真实社区整理
> - `user_contribution`：用户贡献

### 4.2 新增 data_verification 字段

```json
{
  "meta": {
    "source_type": "ai_synthesized_interview",
    "source_detail": "AI 基于公开社区信息（知乎、V2EX、脉脉等）综合生成的模拟访谈数据",
    "data_verification": {
      "is_verified": false,
      "verified_by": null,
      "verified_at": null,
      "verification_note": "合成数据，待真实从业者验证后升级"
    },
    "quality_score": 4.5,
    "review_status": "approved"
  }
}
```

### 4.3 修改 source_detail 表述

所有种子数据的 source_detail 必须诚实标注为 AI 合成，不再使用"访谈：某公司工程师"这种暗示真实访谈的表述。

## 五、Prompt 模板中的幻觉边界注入位置

```
系统 Prompt 结构：

[角色定义]
你是一位求职顾问，帮助求职者理解招聘 JD 背后的真实含义...

[幻觉边界规则] ← 新增
1. 禁止编造具体来源（公司名、人名、访谈场景）
2. 禁止编造具体数字（薪资、百分比、统计数据）
3. 标注不确定性（使用"大多数情况下"、"部分公司可能"等表述）
4. JD 原文优先（不曲解 JD 明确写的内容）
5. 知识库数据诚实标注（使用"从业者社区公开讨论整理"而非"真实访谈"）

[知识库数据注入]
## 来自从业者社区公开讨论整理的经验：
（格式化后的知识库数据）

[用户输入]
JD 文本：...
岗位类别：...
用户背景：...

[输出格式要求]
请按以下维度生成分层结构化报告：
...
```

## 六、验证标准

| 检查项 | 验证方式 | 通过标准 |
|--------|---------|---------|
| 无编造来源 | 人工检查 10 条解读报告 | 0 次出现虚构的公司名/人名/访谈场景 |
| 无编造数字 | 人工检查 10 条解读报告 | 0 次出现未标注来源的具体薪资/百分比 |
| 不确定性标注 | 人工检查 10 条解读报告 | 100% 的推测性内容使用了不确定性表述 |
| JD 原文优先 | 对比 JD 原文与解读报告 | 0 次曲解 JD 明确写的内容 |
| 数据来源声明 | 检查每份报告底部 | 100% 包含数据来源说明 |
